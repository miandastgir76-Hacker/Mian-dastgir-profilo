# Portfolio plan — Mian Ghulam Dastgir Azam

## Direction

Use a pale-green base with near-black sections for contrast. The style should feel focused, warm, and confident: large type, generous spacing, small organic green details, and scroll-reveal movement. The profile area sits in a rounded vertical frame with a black "V" corner accent; add a clear photo when available.

## Recommended page order

1. **Hero:** Name, honest headline, short positioning statement, GitHub and project links.
2. **Selected work:** The three strongest personal projects on the homepage, with a link to the complete project library.
3. **Skills:** A concise list of tools you actively use or study. Keep only skills you can explain or demonstrate.
4. **About:** A short, truthful learning-focused story and principles for your work.
5. **Contact:** An email address or social profile you are comfortable publishing.

## Project-card formula

For each project, use: **what it is**, **what it does**, **tools used**, **current status**, and a **GitHub/demo link** when ready. Do not claim client outcomes, deployments, users, or qualifications unless you can verify them. This version deliberately shows personal projects only.

Example: “Gmail AI Classification Workflow — Personal Project. A workflow exploring AI-assisted Gmail categorisation and organisation. Built with n8n, Gmail, and AI tools. Current stage: learning prototype.”

## Before publishing

- Replace the photo placeholder with a clear, friendly headshot.
- Replace the GitHub and email placeholders in `index.html`.
- Add working links for each project when available.
- Review every project label; only use **Permitted Client Work** with explicit permission.
- Publish free with GitHub Pages, Netlify, or Vercel once the text and links are ready.

## Editing this version

Open `admin.html` in a browser and sign in to manage your profile, projects, skills, and profile photo. The default password is `change-this-password`; change the `ADMIN_PASSWORD` value near the top of `app.js` before use. Those changes stay in that browser only. To make edits permanent for every visitor, update the default data near the top of `app.js`, then re-publish the files. For a real secure public admin login, connect the site to a backend or CMS.
